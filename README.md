# پروژه مدیریت کتابخانه (Library Management)

## معرفی پروژه

این پروژه یک سیستم مدیریت کتابخانه است که با استفاده از Java و Spring Boot توسعه داده شده است.

هدف پروژه، پیاده‌سازی APIهای مربوط به مدیریت کتاب‌ها، کاربران و عملیات امانت گرفتن و بازگرداندن کتاب‌ها است.

در این سیستم امکان ثبت و ویرایش کتاب، جستجو و فیلتر کتاب‌ها، ثبت کاربران، امانت گرفتن کتاب و ثبت تاریخ بازگشت آن وجود دارد.

## تکنولوژی‌های استفاده‌شده

- Java 17
- Spring Boot
- Spring Data JPA
- Hibernate
- MySQL
- Maven
- MapStruct
- Jakarta Bean Validation
- JUnit 5

## پیش‌نیازها

برای اجرای پروژه به موارد زیر نیاز دارید:

- نصب JDK 17 یا بالاتر
- نصب MySQL
- Git

## تنظیم دیتابیس

ابتدا یک دیتابیس با نام `library` در MySQL ایجاد کنید:

CREATE DATABASE library;

سپس اطلاعات اتصال به دیتابیس را در فایل زیر تنظیم کنید:

`src/main/resources/application.properties`

نمونه تنظیمات:


spring.application.name=library_management

spring.datasource.url=jdbc:mysql://localhost:3306/library
spring.datasource.username=root
spring.datasource.password=your_password

spring.jpa.hibernate.ddl-auto=update


مقدار `username` و `password` را متناسب با تنظیمات MySQL خود تغییر دهید.

## نحوه اجرای پروژه

ابتدا پروژه را دریافت کنید:


git clone YOUR_REPOSITORY_URL


وارد پوشه پروژه شوید:


cd library_management


سپس با استفاده از Maven Wrapper پروژه را اجرا کنید.

در ویندوز:


.\mvnw.cmd spring-boot:run


در Linux:


./mvnw spring-boot:run


پس از اجرای موفق، برنامه روی آدرس زیر در دسترس خواهد بود:

`http://localhost:8080`

## اجرای تست‌ها

برای اجرای تست‌های پروژه از دستور زیر استفاده کنید:

در ویندوز:


.\mvnw.cmd test


در Linux:

./mvnw test


برای نوشتن Unit Test از JUnit 5 و Mockito استفاده شده است.

تست‌ها بخش‌های اصلی Serviceها و سناریوهای موفق و ناموفق عملیات را بررسی می‌کنند.

## ساختار پروژه

پروژه به چند بخش اصلی تقسیم شده است:

| پوشه       | توضیحات                           |
| ---------- | --------------------------------- |
| controller | دریافت درخواست‌ها و مدیریت APIها  |
| service    | پیاده‌سازی منطق کسب‌وکار          |
| repository | ارتباط با دیتابیس                 |
| model      | تعریف Entityهای پروژه             |
| dto        | تعریف کلاس‌های Request و Response |
| mapper     | تبدیل Entityها به DTO و برعکس     |
| exception  | مدیریت خطاها و Exceptionها        |

## امکانات پروژه

### مدیریت کتاب‌ها

- ثبت کتاب جدید
- مشاهده اطلاعات کتاب با شناسه
- جستجوی کتاب بر اساس ISBN
- ویرایش عنوان، نویسنده و سال انتشار
- غیرفعال کردن کتاب بدون حذف اطلاعات از دیتابیس
- دریافت لیست کتاب‌ها با Pagination و Sorting
- جستجو بر اساس عنوان، نویسنده و سال انتشار
- فیلتر کتاب‌های قابل امانت

### مدیریت کاربران

- ثبت کاربر جدید
- جستجوی کاربر با کد ملی
- ویرایش اطلاعات کاربر
- دریافت لیست کاربران با Pagination

### مدیریت امانت کتاب

- ثبت امانت کتاب برای کاربران
- جلوگیری از امانت گرفتن کتابی که قبلاً امانت داده شده است
- جلوگیری از امانت گرفتن کتاب غیرفعال
- ثبت تاریخ شروع امانت
- ثبت تاریخ بازگشت کتاب
- تغییر وضعیت کتاب پس از امانت گرفتن و بازگرداندن
- نگهداری سوابق امانت کتاب‌ها

## تصمیمات طراحی

### ۱. استفاده از Entity جداگانه برای امانت کتاب

برای مدیریت عملیات امانت، یک Entity جداگانه با نام `BookBorrowed` ایجاد کردم.

این کلاس ارتباط بین کتاب و کاربر را نگهداری می‌کند و شامل تاریخ شروع امانت و تاریخ بازگشت است.

به این شکل، با بازگرداندن کتاب اطلاعات امانت قبلی حذف نمی‌شود و سوابق امانت کتاب در دیتابیس باقی می‌ماند.

### ۲. استفاده از Soft Delete

برای حذف کتاب از حذف فیزیکی استفاده نکردم، چون ممکن است کتاب قبلاً امانت داده شده باشد و نیاز به نگهداری اطلاعات و سوابق آن داشته باشیم.

به همین دلیل برای کتاب‌ها سه وضعیت در نظر گرفتم:

- `AVAILABLE`: کتاب قابل امانت است.
- `BORROWED`: کتاب در حال امانت است.
- `DEACTIVATED`: کتاب غیرفعال شده است.

همچنین اجازه غیرفعال کردن کتابی که در حال حاضر امانت داده شده است وجود ندارد.

### ۳. استفاده از DTO و MapStruct

برای دریافت اطلاعات از کاربر و ارسال پاسخ API از DTO استفاده کردم تا Entityها مستقیماً در Controllerها استفاده نشوند.

همچنین برای تبدیل Entityها به DTO و برعکس از MapStruct استفاده کردم تا عملیات Mapping ساده‌تر شود و کدهای تکراری کاهش پیدا کنند.
